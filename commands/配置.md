在用户机器上定位本 skill 的 `ac.py`（优先 `~/.workbuddy/skills/agnes-clip-平哥分享版/scripts/ac.py`，其次当前项目 `.workbuddy/skills/agnes-clip-平哥分享版/scripts/ac.py`，兼容目录名带"分享版"或英文名的情况），然后：

1. 用 WorkBuddy 自带的 Python 3.13.12 运行（**不要用 3.14.3**，那个环境已损坏）：
   `<python3.13.12> <ac.py路径> config-ui --no-open --dir "$ARGUMENTS"`
2. 拿到访问地址（默认 http://127.0.0.1:8765/），用系统命令打开浏览器：
   Windows 用 `os.startfile(url)` 或 `start "" "<url>"`；macOS 用 `open "<url>"`。
3. 告诉用户：配置页是后台常驻进程，**那个终端窗口不能关**，关了页面就断。

如果 `--dir` 没给参数，就先扫描当前工作区里有没有 `project.json` 里有 `title` 字段的项目目录，有就把最近一个填进去。

配置页能做的事：
- **总览**：一眼看全 6 条通道的模型/端点/Key
- **生图**：切 Agnes / GPT Image / 自定义 OpenAI 兼容通道，填端点和 Key
- **推理编剧 / 生视频 / 配音 / 配乐**：各自独立的端点、模型、Key
- **系统**：其它杂项

改完点「保存配置」会写进 `~/.workbuddy/agnes-clip.json`（全局生效）。

**别忘了告诉用户一个坑**：如果配了第三方中转（apibase.cc 之类），本 skill 发请求时**已经自动带完整浏览器头**（User-Agent / Accept / Accept-Language / Sec-CH-UA / Origin / Referer），对方用 Cloudflare 拦 Python 默认 UA 也拦不住，一般不用管。如果还是报 403（error code 1010），多半是有人改过 `scripts/ac.py` 里的 `BROWSER_HEADERS`，恢复原样即可。
